# 部署说明与新增算法指南

## 1. 环境要求

| 软件 | 版本 | 说明 |
|---|---|---|
| Python | 3.12 | 由 [uv](https://docs.astral.sh/uv/) 自动安装和管理，无需手动安装 |
| uv | 0.5 以上 | Python 依赖管理 |
| Node.js | 20 以上 | 仅构建前端时需要 |
| pnpm | 9 | 前端依赖管理（`npm i -g pnpm`） |
| 大模型接口 | 任意 OpenAI 兼容接口 | 如 OpenAI、DeepSeek、通义千问、硅基流动或中转站；只有"智能助手"需要，回测与算法库可离线使用 |

行情数据快照已随仓库提供（`data/market/`），不需要联网下载即可回测。

## 2. 快速启动

```bash
git clone <仓库地址>
cd 面向教学的智能体驱动量化算法策略平台

# 可选：配置默认大模型接口（也可以启动后在页面「模型设置」里添加）
cp .env.example .env    # 填写 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL、LLM_FALLBACK_MODEL

./start.sh              # 安装依赖 → 构建前端 → 启动服务
```

浏览器打开 <http://localhost:8000> 即可使用。`start.sh` 做了三件事：

1. `cd backend && uv sync`：安装 Python 依赖（首次会自动下载 Python 3.12）；
2. `cd frontend && pnpm install && pnpm build`：构建前端（已构建过则跳过，加 `--build` 强制重新构建）；
3. `uv run python -m uvicorn api.main:app`：启动后端，同时托管前端页面和 `/api` 接口。

### Windows

先安装 uv 和（需要构建前端时）Node.js 20+、pnpm：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"   # 安装 uv，装完重新打开窗口
npm i -g pnpm                                                                        # 安装 Node.js 后执行
```

然后**双击项目根目录的 `start.bat`** 即可，步骤与 `start.sh` 相同，服务就绪后会自动打开浏览器；关闭窗口或按 Ctrl+C 停止。也可以在 PowerShell 中带参数运行：

```powershell
.\start.bat -Build        # 强制重新构建前端
.\start.bat -NoBrowser    # 不自动打开浏览器
$env:PORT = "8001"; .\start.bat   # 换端口
```

说明：

- `start.bat` 只是用 `-ExecutionPolicy Bypass` 调起 `start.ps1`，所以不需要修改系统的 PowerShell 执行策略；
- 脚本会设置 `PYTHONUTF8=1`，避免中文 Windows 默认 GBK 编码导致的乱码；
- 端口已被占用时会直接提示（通常是平台已经在运行）；
- Windows 的 Python 环境放在 `backend\.venv-windows`，与 Linux / WSL 的 `backend\.venv` 分开。同一个项目文件夹可以在 Windows 和 WSL 之间共用或来回迁移，两边互不影响。Windows 下手动执行 `uv` 命令（如开发模式、运行测试）前，先在 PowerShell 中执行 `$env:UV_PROJECT_ENVIRONMENT = ".venv-windows"`（在 `backend` 目录下）；
- `frontend\node_modules` 不能跨系统共用。从 Linux 迁移过来的文件夹里如果已有 `frontend\dist`，Windows 直接用即可，不需要重新构建；
- 项目路径含中文没有问题；如果 `pnpm install` 报路径过长，把项目放到较短的路径（如 `D:\quant`）下。

### 环境变量

可用环境变量 `HOST`、`PORT` 修改监听地址和端口，`BACKTEST_WORKERS` 设置回测计算进程数（默认 2，0 表示不用进程池）。多人同时使用（如整个班级）时可以调大，每个进程约占 300 MB 内存。

> **安全提示**：平台没有登录鉴权，默认只监听本机 `127.0.0.1`。如果设置 `HOST=0.0.0.0` 让局域网内其他电脑访问，同一网络的任何人都能使用对话（消耗你的大模型额度）、修改模型设置。请只在可信网络中开放，或在前面加一层带鉴权的反向代理。API Key 只保存在后端数据库中，接口返回时已做掩码。

## 3. 开发模式

前后端分开启动，前端修改即时生效：

```bash
# 终端 1：后端（自动重载）
cd backend
uv run uvicorn api.main:app --reload --port 8000

# 终端 2：前端开发服务器（/api 请求自动代理到 8000 端口）
cd frontend
pnpm install
pnpm dev               # 打开 http://localhost:5173
```

## 4. 配置大模型

两种方式，效果相同：

1. **页面配置（推荐）**：左下角「模型设置」→「添加接口」→ 选择服务商模板或填写 API 地址 → 填写 API Key → 点「获取模型列表」勾选模型（接口不支持列表时可手动填写模型名）→ 保存；然后在「调用顺序」中选择主模型，并添加备用模型。每个模型都可以点「测试」检查连通性、延迟和是否支持工具调用。
2. **环境文件**：项目根目录 `.env`（参考 `.env.example`）。仅在数据库中还没有任何接口时，首次启动会把它写入「模型设置」，之后以页面配置为准。

主模型请求失败、超时或返回空内容时，会按顺序自动切换到备用模型，并在对话中提示。

> 智能体依赖模型的**工具调用（function calling）**能力，请选择支持该能力的模型；「测试」按钮会显示检测结果。

## 7. 新增量化算法

以"唐奇安通道突破（股票）"为例，三步完成，不需要修改任何其他代码。

### 第 1 步：编写策略类

新建 `backend/quant/strategies/stock/donchian_breakout.py`：

```python
from pydantic import Field, model_validator

from ..base import Strategy, StrategyOutput, register
from ..common import StopParams, apply_stops, pool_weights, state_machine
from ..indicators import donchian


class Params(StopParams):  # 继承 StopParams 自动获得止损、止盈参数
    entry_window: int = Field(20, ge=5, le=120, title="突破周期",
                              description="收盘价突破过去 N 日最高价时买入")
    exit_window: int = Field(10, ge=3, le=60, title="离场周期",
                             description="收盘价跌破过去 M 日最低价时卖出")
    position_ratio: float = Field(1.0, gt=0, le=1, title="总仓位比例",
                                  description="股票池等分资金后，每只股票满仓时占其资金槽位的比例")

    @model_validator(mode="after")
    def _check(self):
        if self.exit_window >= self.entry_window:
            raise ValueError("离场周期应小于突破周期")
        return self


@register
class DonchianBreakoutStock(Strategy):
    id = "donchian_breakout_stock"          # 全局唯一
    name = "唐奇安通道突破"
    category = "stock"                      # stock 或 futures
    style = "趋势跟踪（通道突破）"
    summary = "收盘价创 N 日新高时买入，跌破 M 日新低时卖出。"
    aliases = ("唐奇安", "通道突破", "唐奇安通道")   # 对话中可以这样称呼它
    Params = Params
    default_universe = "stock_pool"         # stock_pool / industries / futures / 逗号分隔的代码
    asset_types = frozenset({"stock", "industry"})

    def generate(self, bars):
        p = self.params
        upper, _ = donchian(bars.high, bars.low, p.entry_window)
        _, lower = donchian(bars.high, bars.low, p.exit_window)
        pos = state_machine(bars.close > upper, bars.close < lower)   # 1 持有 / 0 空仓
        pos = apply_stops(pos, bars.close, p.stop_loss, p.take_profit)
        return StrategyOutput(
            weights=pool_weights(pos, p.position_ratio),   # 目标权重：日期 × 标的
            indicators={"通道上轨": upper, "离场下轨": lower},  # 会画在交易点位图上
        )
```

要点：

- `generate` 只能使用 `bars` 中截至当天收盘的数据（滚动窗口、`shift` 都是安全的），返回**目标权重**即可，成交、费用、涨跌停由引擎处理；
- 期货策略的权重可以为负（做空），通常写成 `pos * p.position_limit`；
- 截面选股类策略可以用 `common.rebalance_mask` 和 `common.top_k_weights`，并把调仓日通过 `StrategyOutput(rebalance=mask)` 传给引擎；
- 可用的指标在 `strategies/indicators.py`：均线、EMA、ATR、RSI、MACD、KDJ、布林带、唐奇安通道、Z 分数、动量、波动率等。

## 8. 常见问题

| 问题 | 解决 |
|---|---|
| 智能助手提示"还没有配置可用的模型" | 到「模型设置」添加接口并选择主模型 |
| 模型测试显示"未检测到工具调用" | 换一个支持 function calling 的模型 |
| 回测报"区间内交易日不足" | 检查区间是否在数据范围内：股票 2016-01 起，期货 2020-01 起 |
| 前端页面空白 | 确认已执行 `pnpm build`，或使用开发模式访问 5173 端口 |
| WSL 下前端修改不生效 | `vite.config.ts` 已开启轮询监听；若仍无效，重启 `pnpm dev` |
| Windows 报 `failed to remove file ...\.venv\lib64: 拒绝访问` | 旧版启动脚本会尝试重建 Linux 下的 `.venv`。更新到新版 `start.bat` 即可，它使用独立的 `.venv-windows`；Linux 端执行一次 `cd backend && uv sync` 修复被删的 `.venv` |
| Windows 双击 `start.bat` 闪退 | 在 PowerShell 中运行 `.\start.bat` 查看报错；最常见的是没装 uv，或装完 uv 后没有重新打开窗口 |
| Windows 提示"无法加载文件 start.ps1，因为在此系统上禁止运行脚本" | 改为运行 `start.bat`，它会临时绕过执行策略 |
